## 준비

- `npm run build && npm run preview` 후 참가자마다 새 창에서 `http://localhost:4173/?fresh=1`. `fresh=1`은 모든 사건의 저장과 진행 상황을 지우고 **Case 0부터** 연다. Case 0을 거치지 않는 비교 그룹은 `?fresh=1&case=friday-1802`(Case 3 바로 열기, 잠금 무시). 한 사건만 볼 때: `?fresh=1&case=case1-cron-env`, `?fresh=1&case=case2-deleted-open`. 움직임에 민감한 참가자는 `&motion=0`(OS의 "동작 줄이기"와 같음).
- 대기 넛지(2단)는 사건 파일 값: Case 0 **2분**, Case 1·2·3 **6분**. 직전 1분 안에 단서를 찾았으면 넛지는 그만큼 기다린다(곧 풀 사람을 끊지 않기). 다른 값을 시험할 때만 `&nudge=5`.
- 진행자는 화면 녹화(또는 옆자리 관찰)와 이 문서의 결과표를 준비한다.
- **스피커나 이어폰을 켠다.** UI 효과음(메시지 딩, 메일, 체크, 핀, 오류, 키 입력 등)은 ZzFX로 브라우저 안에서 합성돼 첫 클릭부터 바로 들린다. 터미널에서 글자를 치면 작은 키 클릭이 난다(세 가지가 무작위, 좌우로 살짝). 음악·환경음·음성은 `public/audio/`의 파일로 재생되고, 환경음 파일이 없으면 브라우저가 사무실 방 톤을 합성해 깐다. 음악은 브리핑·해설에서 한 번씩만 울리고 계속 돌지 않는다(루프는 환경음뿐). 음량은 참가자가 작업 표시줄 🔊 로 바꿀 수 있고, 바꾼 기록이 로그에 남는다.
- 첫 3분은 **스톱워치를 따로 켠다**: 잠금 해제 버튼을 누른 순간 시작. 진행자는 이 3분 동안 어떤 질문에도 "화면을 따라가 보세요"만 답한다.
- 진행자용 URL 옵션: `?briefing=0` 브리핑 없이 시작(비교용), `?bspeed=2` 브리핑 2배속(리허설용).
- 로그는 사건마다 따로다. **사건마다 해설 화면에서 한 번씩**(해설 아래 📋 버튼) 저장한다.
- 플레이가 끝나면 작업 표시줄 📋 → **플레이 로그 JSON 저장**. 파일 이름에 참가자 번호를 붙인다(P1~P5). 로그는 어디에도 전송되지 않는다.
